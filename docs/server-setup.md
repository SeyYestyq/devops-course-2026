# Конфигурация виртуальной машины devops-vm

Документация параметров и этапов настройки целевого сервера `devops-vm` (ОС Ubuntu Server 24.04 LTS). Предназначена для быстрого воспроизведения конфигурации вручную (в пределах 10 минут) при откате на снимок `01-clean-install`, а также в качестве спецификации при разработке Ansible-ролей в практической работе № 11.

---

## 1. Параметры машины

| Параметр | Значение | Описание / Назначение |
| :--- | :--- | :--- |
| **Наименование ВМ** | `devops-vm` | Имя виртуальной машины в гипервизоре VirtualBox |
| **Тип гостевой ОС** | Linux / Ubuntu (64-bit) | Базовый дистрибутив: Ubuntu Server 24.04 LTS (Noble Numbat) |
| **Оперативная память** | 2048 МБ (2 ГБ) | Выделенный объём RAM для стабильной работы служб и контейнеров |
| **Количество CPU** | 2 ядра | Выделенные вычислительные ядра хостового процессора |
| **Дисковый накопитель** | 25 ГБ | Динамически расширяемый образ виртуального диска (VDI) |
| **Графический интерфейс** | Отсутствует | Headless/Server редакция (минимизация потребления ресурсов и attack surface) |

---

## 2. Сетевые интерфейсы

Виртуальная машина использует двухсетевую архитектуру:

| Адаптер | Тип адаптера VirtualBox | IP-адрес в гостевой ОС | Назначение и маршрутизация |
| :--- | :--- | :--- | :--- |
| **Адаптер 1 (enp0s3)** | NAT | `10.0.2.15/24` (шлюз `10.0.2.2`) | Доступ гостевой ОС в интернет (загрузка пакетов `apt`, обновлений, образов). Прямой входящий доступ с хоста невозможен, кроме проброшенных портов. |
| **Адаптер 2 (enp0s8)** | Виртуальный адаптер хоста (*Host-only*) | `192.168.56.101/24` (статический / выданный DHCP Host-only) | Изолированный сегмент между хостом и ВМ. Прямой доступ к службам (SSH, Nginx веб-сервер) с хостовой машины без маршрутизации в общую сеть. |

---

## 3. Правило проброса портов

Настроено в свойствах **Адаптера 1 (NAT)** в VirtualBox:

| Наименование правила | Протокол | Адрес хоста | Порт хоста | Адрес гостя | Порт гостя |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `ssh` | TCP | `127.0.0.1` | `2222` | *(не заполняется)* | `2222` |

> **Важно:** Первоначально порт гостевой системы был установлен в `22`. После выполнения процедуры hardening (перенос SSH на порт `2222`) значение порта гостя изменено на `2222`.

## 4. Учётные записи

| Имя пользователя | UID / GID | Группы | Способ аутентификации | Назначение |
| :--- | :--- | :--- | :--- | :--- |
| `student` | `1000:1000` | `student, adm, cdrom, sudo, dip, plugdev, lxd` | Пароль (установлен при установке ОС) | Первичная сервисная учётная запись инсталлятора |
| `devops` | `1001:1001` | `devops, sudo` | **Исключительно по SSH-ключу** (Ed25519) | Основная учётная запись администратора для удалённого управления |
| `root` | `0:0` | `root` | Заблокирован для прямого SSH-входа (`PermitRootLogin no`) | Суперпользователь системы; доступен через `sudo` |

### Настройка прав доступа к SSH-материалам пользователя `devops`:
```bash
# На сервере:
chmod 700 /home/devops/.ssh
chmod 600 /home/devops/.ssh/authorized_keys
chown -R devops:devops /home/devops/.ssh
```

## 5. Служба SSH

* **Файл конфигурации:** `/etc/ssh/sshd_config.d/99-hardening.conf` (основной файл `/etc/ssh/sshd_config` сохранён в эталонной резервной копии `/etc/ssh/sshd_config.backup`).
* **Особенности Ubuntu 24.04:** Механизм активации по сокету отключён для предотвращения возврата порта на 22:
  ```bash
  sudo systemctl disable --now ssh.socket
  sudo systemctl enable --now ssh.service
  ```
* **Разрешение конфликта с cloud-init:** В файле `/etc/ssh/sshd_config.d/50-cloud-init.conf` закомментирована директива `PasswordAuthentication yes`.

### Содержимое конфигурационного файла `/etc/ssh/sshd_config.d/99-hardening.conf`:
```ini
Port 2222
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
PermitEmptyPasswords no
MaxAuthTries 3
LoginGraceTime 30
AllowUsers devops
X11Forwarding no
ClientAliveInterval 300
ClientAliveCountMax 2
```

### Назначение ключевых директив:
* `Port 2222` — перенос службы с дефолтного 22 порта для отсечения массовых ботнет-сканеров.
* `PermitRootLogin no` — запрет входа суперпользователя напрямую по SSH.
* `PasswordAuthentication no` — полное отключение аутентификации по паролю (защита от брутфорса).
* `PubkeyAuthentication yes` — разрешение входа по криптографическим асимметричным ключам.
* `PermitEmptyPasswords no` — запрет входа с пустыми паролями.
* `MaxAuthTries 3` — ограничение попыток аутентификации до трёх на одну сессию.
* `LoginGraceTime 30` — отключение клиента при отсутствии аутентификации за 30 секунд.
* `AllowUsers devops` — ограничение списка учётных записей с правом SSH-подключения.
* `X11Forwarding no` — отключение проброса графических окон.
* `ClientAliveInterval 300` и `ClientAliveCountMax 2` — проверка активности сессии и предотвращение зависших соединений.

## 6. Правила межсетевого экрана (UFW)

Межсетевой экран активен и сконфигурирован по принципу «запрещено всё, что не разрешено явно».

### Политики по умолчанию:
* **Входящий трафик (Incoming):** `DENY` (блокировать все входящие соединения)
* **Исходящий трафик (Outgoing):** `ALLOW` (разрешить все исходящие соединения)
* **Маршрутизируемый трафик (Routed):** `DISABLED`

### Действующие правила:
| Номер | Порт / Протокол | Действие | Описание / Назначение |
| :---: | :--- | :--- | :--- |
| **1** | `2222/tcp` | **LIMIT** | Управляющий порт SSH с ограничением частоты подключений (не более 6 за 30 сек) |
| **2** | `80/tcp` | **ALLOW** | Входящий HTTP-трафик для веб-сервера Nginx (к практической работе № 6) |
| **3** | `443/tcp` | **ALLOW** | Входящий HTTPS-трафик для защищённых соединений TLS |

### Команды быстрого развёртывания UFW:
```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw limit 2222/tcp comment 'SSH rate-limited'
sudo ufw allow 80/tcp comment 'HTTP'
sudo ufw allow 443/tcp comment 'HTTPS'
sudo ufw --force enable
sudo ufw logging medium
```

## 7. Снимки состояния (Snapshots)

Снимки созданы в менеджере VirtualBox для фиксации контрольных точек прогресса и обеспечения возможности мгновенного отката при сбоях:

| Наименование снимка | Момент создания | Состояние виртуальной машины |
| :--- | :--- | :--- |
| **`01-clean-install`** | После чистой установки Ubuntu Server 24.04 LTS и выполнения `sudo apt update && sudo apt upgrade -y`. | Чистая базовая ОС, сеть enp0s3 (NAT) и enp0s8 (Host-only) активны, пользователь `student`, SSH на порту 22. Точка восстановления для быстрой перенастройки. |
| **`02-keys-configured`** | После создания пользователя `devops`, добавления в группу `sudo` и настройки беспарольного входа по Ed25519-ключу с хоста. | Пользователь `devops` настроен, права `700` и `600` валидированы, проверено подключение `ssh devops`. |
| **`03-ssh-hardened`** | После создания `/etc/ssh/sshd_config.d/99-hardening.conf`, отключения `ssh.socket`, перевода SSH на порт `2222`, настройки правил UFW и проверки доменного имени `devops.local`. | Полностью защищённая целевая конфигурация: SSH на 2222, root и пароли закрыты, UFW активен с правилом `LIMIT 2222/tcp`, разрешено FQDN `devops-vm.devops.local`. |

## Процедура быстрого восстановления конфигурации (до 10 минут)

В случае отката на снимок `01-clean-install`:
1. Подключиться: `ssh student@127.0.0.1 -p 2222`
2. Создать пользователя: `sudo adduser --gecos "" devops && sudo usermod -aG sudo devops`
3. Скопировать ключ с хоста: `ssh-copy-id -i ~/.ssh/devops_vm.pub -p 2222 devops@127.0.0.1`
4. Добавить конфигурационный файл: `sudo tee /etc/ssh/sshd_config.d/99-hardening.conf` с параметрами раздела 5
5. Закомментировать конфликт в `50-cloud-init.conf` (если имеется)
6. Переключить systemd сокет: `sudo systemctl disable --now ssh.socket && sudo systemctl enable --now ssh.service && sudo systemctl restart ssh`
7. В свойствах ВМ в VirtualBox изменить гостевой порт правила `ssh` с `22` на `2222`
8. Настроить UFW: `sudo ufw default deny incoming && sudo ufw default allow outgoing && sudo ufw limit 2222/tcp && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp && sudo ufw --force enable`
9. Назначить имя: `sudo hostnamectl set-hostname devops-vm`
10. Проверить аудит: `./scripts/audit.sh`
