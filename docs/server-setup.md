## 9. Контейнеризация (Практическая работа № 7)

### 9.1 Установка Docker Engine
* **Способ установки:** Установка из официального репозитория Docker (`https://download.docker.com/linux/ubuntu`) в соответствии с официальным руководством Docker Docs (пакет `docker-ce`, `docker-ce-cli`, `containerd.io`, `docker-buildx-plugin`, `docker-compose-plugin`). Дистрибутивный пакет `docker.io` не используется.
* **Версия Docker Engine:** `Docker version 28.0.1, build 068a01e` (API version 1.48)
* **Версия Docker Compose:** `Docker Compose version v2.33.1`

### 9.2 Привилегии и пользователи
* **Участники группы `docker`:** учётная запись `devops` (`sudo usermod -aG docker devops`).
* *Безопасность:* Учётные записи без прав `sudo` в группу `docker` не включаются, так как доступ к сокету Docker эквивалентен получению привилегий суперпользователя `root` на хосте.
* **Внутриконтейнерные пользователи:** 
  * Контейнер приложения: непривилегированный пользователь `app` (UID 999/1000), созданный через `RUN useradd --system --no-create-home app`.
  * Контейнер базы данных: системный пользователь `postgres` (UID 70 в alpine).

### 9.3 Расположение проектов и файлов конфигурации
* **Каталог проекта на сервере:** `/home/devops/app`
* **Файл переменных окружения:** `/home/devops/app/.env`
  * **Права доступа:** `600` (`-rw-------`), владелец `devops:devops`.
  * **Секреты:** Содержит пароль `POSTGRES_PASSWORD`, сгенерированный на сервере (`openssl rand -hex 16`). Файл исключён из Git (`.gitignore`) и из контекста сборки (`.dockerignore`). Доставка на сервер выполняется с ключом `--exclude=.env`.
  * **Шаблон:** `app/.env.example` с именами переменных и заглушками.

### 9.4 Публикация портов и сетевая изоляция
* **Приложение (`app`):** Порт опубликован строго на локальной петле: `127.0.0.1:5000:5000`. Прямой внешний доступ из сети запрещён.
* **СУБД (`db`):** Порт `5432` во внешнюю сеть **не публикуется**. Доступ к СУБД разрешён исключительно контейнеру приложения через внутреннюю сеть Docker.
* **Сеть Docker:** Изолированная пользовательская сеть типа bridge `backend`. Разрешение имён сервисов выполняется встроенным DNS Docker (`db` -> внутренний IP контейнера).

### 9.5 Хранилище данных (Volumes)
* **Именованный том:** `app_db_data` (в docker-compose: `db_data`), смонтирован в каталог `/var/lib/postgresql/data`.
* Обеспечивает персистентность данных счётчика посещений при перезапусках контейнеров (`docker compose down && docker compose up -d`).

### 9.6 Конфигурация обратного прокси-сервера (Nginx)
В конфигурационный файл `/etc/nginx/sites-available/devops-site` в блок `server` с TLS (порт 443) добавлен блок обратного проксирования:
```nginx
location /app/ {
    proxy_pass http://127.0.0.1:5000/;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```
* Завершающий слеш `/` в директиве `proxy_pass` заменяет URI-префикс `/app/` на `/`, благодаря чему запрос к `https://devops.local/app/health` корректно поступает в контейнер приложения по адресу `http://127.0.0.1:5000/health`.
* При остановке контейнера приложения Nginx возвращает штатный HTTP-код `502 Bad Gateway` и регистрирует отказ в `/var/log/nginx/devops-site.error.log`.
